# TypeScript (TS)
1. TypeScript is JavaScript with syntax for types
2. TS is a superset of JavaScript; TS code is converted into JS with the help of TS compiler
3. JS is runtime programming lang, TS is compile-time programming lang i.e we decide the variable type during compile-time
4. TS is strongly typed programming language that builds on JavaScript, giving us better tooling at any scale 
5. TS understands JS and uses 'type inference' to give us great tooling without additional code.


## Basic Fundamentals 1

Check whether TS is installed on your machine from Terminal
* mac command   : tsc -v
* windows cmd: tsc --version

if, command not found: tsc ; then install through npm package
* macOS:  sudo npm install -g typescript
* windows: npm install -g typescript

How to run the .ts file from terminal?
* 1stCommand => tsc filename.ts  // here TS Compiler (tsc) generates filename.js from filename.ts
* 2ndCommand => node filename.js // we get the actual output of TS 

## Basic Fundamentals 3
If a .ts file has no import or export, TypeScript treats it as a Script, and all scripts in the project share one global scope. That causes the problems below:
1. Name clashes between files
```TypeScript
    // 101_helloTS.ts
    let firstName: string = "Priya";

    // 102_TS_concepts.ts
    let firstName: string = "Susagar";   // ❌ TS2451: Cannot redeclare block-scoped variable 'firstName'
```
Both files declare the same global name. The same happens with const, class, function, interface and type.

2. Red underlines in VS Code
3. Compiling the whole project fails
4. Accidental clashes with built-in globals: Script files also share the global scope with browser and Node type definitions, so common names can collide
5. Variables leak across files: A script file’s top-level declarations become globally visible to other script files, so one file can accidentally use or overwrite another file’s variable.
6. Type-only differences

## One-line summary:
* without `export {};` the file is a script that shares one global scope with every other script, so duplicate names across files, and collisions with built-in globals, cause TypeScript errors.
* with `export {};` turns a file into a module, so its variables stay private to that file instead of sharing one global scope.
